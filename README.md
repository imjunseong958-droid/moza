# MOZA — 성인 절대음감 훈련

Wong, Cheung, Ngan & Wong (2025) *Learning fast and accurate absolute pitch judgment in adulthood* (Psychonomic Bulletin & Review, doi:10.3758/s13423-024-02620-2)의 훈련 프로토콜을 옮긴 브라우저 앱입니다. 이 논문에서는 성인 음악인 12명이 8주 동안 평균 21시간 훈련해서 평균 7개 음을 익혔고, 그중 2명은 12음 전부를 익혔습니다.

## 설치

Node 23.6 이상이 필요합니다.

```sh
git clone https://github.com/imjunseong958-droid/moza.git
cd moza
npm link   # 터미널 어디서나 moza 명령을 쓸 수 있게 등록
```

## 실행

```sh
moza
```

로컬 서버(http://127.0.0.1:4810)가 뜨고 브라우저가 열립니다. 끝낼 때는 터미널에서 Ctrl+C를 누르세요.

- Node 23.6 이상이 필요합니다. `.ts`를 빌드 없이 바로 실행합니다. 브라우저로 보내는 `.ts` 파일도 서버가 타입만 지워서 보냅니다.
- 기록은 `~/.moza/state.json`에 저장되고, 하루에 한 번 `~/.moza/backups/`에 사본이 남습니다.
- 옵션: `--port`, `--no-open`, `--data-dir` (`moza --help`)

## 훈련 방식

| | 내용 | 근거 |
|---|---|---|
| 음 추가 순서 | F에서 시작해 E, F#, D#, G … 순서로 아래·위를 번갈아 추가 | 논문 |
| 레벨 | 음마다 24레벨, 모두 288레벨 | 논문 |
| 문제 시작 | 참가자가 ▶(Enter)를 눌러 문제마다 직접 시작 | 논문 |
| 통과 기준 | 20% → 90% | 논문(범위) |
| 마지막 레벨 제한 시간 | 음 1개일 때 1183ms … 12개일 때 2028ms | 논문 보충자료 Table 1 |
| 범위 밖 음 | 세트 양 끝 ±1·±2반음을 섞고, 세트가 커질수록 줄임 | 논문 |
| 셰퍼드 톤 | 정답을 알려주지 않는 레벨 전에 20초 (같은 레벨을 다시 할 때는 생략할 수 있음) | 논문 (생략은 바꾼 부분) |
| 소리 | 피아노 C4–B6, 0.8초, 끝 0.1초 페이드 | 논문 |
| 약점 집중 연습 | 음 5개부터 15레벨마다: 정답 알려줌 12문제 + 안 알려줌 22문제 | 논문 |
| 레벨 건너뛰기 | 이번 결과가 더 높은 레벨의 기준을 넘으면 그 레벨로 | 논문 |
| 졸업 | 레벨 288을 3번 연속 통과하고, 12시간 쉰 뒤 한 번에 통과. 졸업하면 F 1단계부터 다음 회차 | 논문 (회차는 바꾼 부분) |
| 하루 목표 | 레벨 24번 도전 (떨어진 레벨도 1번). 시간은 재지 않음 | 바꾼 부분 (논문은 8주 25시간) |
| 테스트 | 12음 × 3옥타브 × 피아노·기타 × 2번 = 144문제, 5초, 연속된 두 음은 12반음보다 멀리 | 논문 |

### 재구성한 부분

논문 본문과 보충자료에는 레벨별 세부 수치가 없어서(OSF 사전등록 자료는 비공개) 아래처럼 채웠습니다. 바꾸려면 `web/src/protocol.ts`를 고치면 됩니다.

- **24레벨 구성:** 12단계 × (정답 알려주는 레벨 → 안 알려주는 레벨). 2020년 선행 연구의 구성과 같습니다.
- **단계별 통과 기준:** 20, 30, 40, 50, 60, 70, 80, 90, 90, 90, 90, 90%
- **단계별 제한 시간:** 마지막 레벨 값 × 4, 4, 3.5, 3, 2.6, 2.3, 2, 1.8, 1.6, 1.4, 1.2, 1 (최대 5초)
- **레벨당 문제 수:** max(12, 6 + 2×음 개수). 음 1개일 때 12문제, 12개일 때 30문제입니다.
- **훈련 중 연속된 두 음:** 7반음 이상 떨어뜨림 (테스트는 논문대로 12반음 초과)
- **다음 문제 시작:** 앞 음이 끝나고 0.5초가 지나야 ▶가 다시 눌림 (앞 음과 붙어서 비교 기준이 생기지 않게)
- **토큰:** 정확도 60%·75%·90%마다 1개씩 받습니다. 2020년 연구 방식입니다.

### 논문과 다르게 바꾼 부분

- **하루 목표:** 논문은 8주 동안 25시간(주 2시간 이상, 15분 미만 세션은 불인정)을 채우게 했습니다. 이 앱은 시간을 재지 않고 하루에 레벨 24번 도전을 목표로 합니다. 레벨을 끝까지 풀면 통과든 실패든 1번이고, 중간에 그만둔 레벨은 세지 않습니다. 처음 몇 음은 하루에 음 하나(24단계)를 끝내는 셈이고, 뒤로 갈수록 레벨당 문제가 늘고 통과가 어려워져 한 음에 며칠씩 걸립니다. 레벨 구성·통과 기준 같은 훈련 내용은 그대로입니다.
- **회차:** 졸업하면 점수·토큰·레벨 기록·테스트는 그대로 두고 진도만 F 1단계로 돌려 다음 회차를 시작합니다. 졸업 뒤 처음 보는 테스트가 사후 테스트입니다.
- **셰퍼드 톤 생략:** 정답을 알려주지 않는 레벨을 끝내고 샘플을 듣지 않은 채 같은 레벨을 다시 하면 셰퍼드 톤을 건너뜁니다. 논문은 셰퍼드 톤을 "들은 샘플 음의 기억을 지우는" 장치로 설명하는데, 이때는 지울 기억이 없어서입니다. 원테이크와 약점 집중 연습 뒤에는 그대로 틉니다.

## 소리

- **피아노:** University of Iowa Electronic Music Studios의 [Musical Instrument Samples](https://theremin.music.uiowa.edu/MISpiano.html)(Steinway & Sons Model B, 2001년 녹음, mf)에서 C4–B6 36음을 썼습니다. 학교 측은 "어떤 프로젝트에도 제한 없이" 쓸 수 있다고 밝히고 있습니다.
  - 모든 음을 따로 녹음한 샘플이라, 음높이를 늘려 만든 음 때문에 음색 차이가 단서가 되는 일이 없습니다.
  - 녹음된 조율은 평균율보다 +4~+20센트 높습니다 (고음일수록 높게 조율하는 스트레치 튜닝).
- **기타(테스트용 낯선 음색):** 같은 곳의 [기타 녹음](https://theremin.music.uiowa.edu/MISguitar.html)(Raimundo 118 클래식 기타, 2011년 무반향실 녹음, mf)을 썼습니다.
  - C4–D#4는 2번 줄, E4–B5는 1번 줄 녹음입니다.
  - 클래식 기타는 B5가 가장 높은 음이라 칠 수 없는 C6–B6은 C5–B5 녹음을 정확히 한 옥타브 올려(2배 속도) 만들었습니다.
  - 녹음된 기타는 평균율보다 8–26센트 낮게 조율돼 있어서, 음마다 A4 = 440Hz 평균율에 맞췄습니다(±2.5센트 이내).
- **크기:** 두 악기 모두 음마다 처음 0.3초 크기(RMS)를 같게 맞춰서, 음량이 정답 단서가 되지 않습니다.
- **셰퍼드 톤, 볼륨 확인 잡음:** 브라우저에서 합성합니다.

샘플을 다시 만들려면 원본 AIFF를 받은 뒤 아래 명령을 실행하세요.

```sh
node tools/build-piano.ts <AIFF 폴더>
node tools/build-guitar.ts <AIF 폴더>
```

- **피아노 폴더:** `Piano.mf.C4.aiff` … `Piano.mf.B6.aiff`가 있어야 합니다.
- **기타 폴더:** `Guitar.mf.sulB.C4B4.mono.aif`, `Guitar.mf.sul_E.E4B4.mono.aif`, `Guitar.mf.sul_E.C5B5.mono.aif`가 있어야 합니다.

도구가 소리 시작점부터 0.8초를 자르고, 음마다 크기를 맞추고, 음높이를 점검한 뒤 `web/sounds/<악기>/<MIDI 번호>.wav`로 저장합니다. 기타는 한 파일에 여러 음이 들어 있어서, 소리가 커지는 지점으로 나눈 뒤 음높이로 어느 음인지 확인합니다.

## 개발

```sh
npm install      # TypeScript 타입 검사용 (실행에는 필요 없음)
npm run check    # tsc: 서버·도구·테스트, 브라우저 코드
npm test         # 프로토콜·하루 목표 계산 테스트
```

브라우저 주소에 `?debug`를 붙이면 콘솔에서 `window.moza`로 상태를 볼 수 있습니다. `?debug&fast`는 셰퍼드 톤을 1초로 줄입니다.

## 기여

변경은 Pull Request로만 받습니다. `main` 브랜치에는 직접 푸시할 수 없습니다. PR을 열기 전에 `npm run check`와 `npm test`가 통과하는지 확인해 주세요.
